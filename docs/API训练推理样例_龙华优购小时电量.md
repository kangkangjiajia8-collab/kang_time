# 龙华供电 · 优购电量：从零到出结果（训练 + 推理）

这份说明写给**完全不懂接口、不懂代码**的人用。你只要按顺序做，能点按钮就点按钮，能复制粘贴就复制粘贴。

---

## 这份文档在帮你干什么？

两件事，顺序不能反：

1. **训练**：把你的历史电量表交给服务器，服务器“学会”规律，最后给你一个 **压缩包（zip）**，里面是模型。
2. **推理**：把同一个压缩包再传上去，再传一张**最近的历史表**，服务器告诉你**接下来 168 个小时**大概多少电（每小时一行）。

业务场景已经定好：

- 数据是**龙华**这一家供电单位；
- 你要预测的那一列名字叫 **「优购」**（表头必须一模一样，不要多空格）；
- 时间粒度是**每小时一行**；
- 要预测的时间段是：**5 月 14 日 0 点** 一直到 **5 月 20 日 23 点**（包含首尾两天），一共 **7 天 × 24 小时 = 168 小时**，所以后面你会反复看到数字 **168**。

---

## 开始之前，你需要有什么？

1. **一台能访问服务器的电脑**（公司内网或已配好的地址，问同事要一个网址，形如 `http://某地址:8000`）。下面用 **`http://127.0.0.1:8000`** 举例，你用时**全部换成你们真实的地址**。
2. **一个表格文件**，用 Excel 做好再另存为 **CSV（逗号分隔）**。不要用复杂格式（xlsx 不能直接传，必须另存为 csv）。
3. **二选一**会操作即可：
   - 会用 **Postman**（或 Apifox 等带界面的接口工具）——**推荐**，不用记命令；
   - 或者有人会帮你在黑色窗口里执行 **curl** 命令。

下面两种方法都会写：**先看 Postman**，再看 **curl**。

---

## 第一步：准备你的 Excel / CSV（最重要）

### 1.1 表至少要长什么样？

做一张表，**第一行是表头（列名）**，从第二行开始是数据。

至少要这三列（列名建议完全一致）：

| 列名 | 这一列放什么 |
|------|----------------|
| `timestamp` | 每一个小时的**具体时间**，例如 `2026-05-01 00:00:00` |
| `item_id` | 这一行属于谁。龙华就**每一行都写 `龙华`**（不要一行龙华一行别的） |
| `优购` | 这一小时**真实用电量**（训练时必须有；推理时也要有**已经过去的那些小时**的真实值） |

**注意：**

- 列名 **`优购`** 两个字要和后面填表里的「目标列」一致，不要改成「优购电量」之类，除非你也改了填表里的名字。
- 时间列也可以叫 `date` 或 `time`，系统有时能认，但**最省事**是直接用 **`timestamp`**。
- 保存成 CSV 时，尽量用 **UTF-8** 编码（Excel 另存为时若有编码选项就选 UTF-8），避免中文乱码。

### 1.2 数字 168 和日期到底怎么对？

你要预测的是从 **5 月 14 日 0 点** 到 **5 月 20 日 23 点**，按小时数一共 **168** 格。

训练用的历史数据，**最后一行**建议停在你要预测的前一天最后一小时，也就是：

- **最后一行时间：`2026-05-13 23:00:00`**

这样系统才会觉得：“下一个小时开始就是 5 月 14 日 0 点”，然后一口气往后预测 168 个小时，正好接到 5 月 20 日 23 点。

如果你最后一行还停在 5 月 10 日，系统照样能跑，但预测出来的“未来 168 小时”对应的**日历日期**会整体往后移——**新手最容易懵的就是这个**，所以尽量按上面把历史对齐到 **5 月 13 日 23 点**。

### 1.3 抄一个最小例子（可对照改）

```csv
item_id,timestamp,优购
龙华,2026-05-01 00:00:00,123.4
龙华,2026-05-01 01:00:00,125.0
龙华,2026-05-01 02:00:00,121.8
```

你自己的表要有很多很多行，一直写到 **5 月 13 日 23 点**。

## 第二步：训练（上传历史表 → 等 → 得到一个 zip）

### 2.1 训练在系统里叫什么？

在浏览器或工具里访问的完整地址是：

```text
http://你的服务器地址:端口/api/train
```

例如端口是 8000：

```text
http://127.0.0.1:8000/api/train
```

**方法 = POST**（在 Postman 里选 POST；用 curl 时已经写在命令里）。

### 2.2 用 Postman 怎么点？（推荐）

1. 新建请求，选 **POST**，地址填上面的 `/api/train` 完整路径。
2. 点 **Body**，选 **form-data**（表单数据），不要选 raw JSON。
3. 一行一行添加下面这些「键值对」。类型选 **Text** 或 **File** 按下面说明来。

**一定要填的（少一个都不行）：**

| Key（键） | 类型选 | Value（值）填什么 |
|-----------|--------|-------------------|
| `task_id` | Text | 随便起**不重复**的名字，例如 `longhua_yougo_20260514`。就像给这次训练起个文件名，**同一次训练不要重复提交同一个名字**。 |
| `file` | **File** | 点选你的 **训练用 CSV 文件**。 |
| `target` | Text | 固定填：`优购`（和表头一致） |
| `prediction_length` | Text | 固定填：`168` |
| `use_tsfresh` | Text | 填：`false`（新手先关，省很多事） |
| `time_limit` | Text | 填：`3600` 表示最多让电脑练 **3600 秒 = 1 小时**。可以改成 `7200` 就是 2 小时，看公司机器快慢。 |
| `enable_ensemble` | Text | 填：`true`（让多个小模型投票，一般更稳） |

**建议填的（不填有时也能跑，但小时数据建议填）：**

| Key | 类型 | Value |
|-----|------|-------|
| `freq` | Text | `H`（表示每小时一条） |

**新手不要碰的（整段删掉或不要添加这一行）：**

- 不要添加 **`hyperparameter_tune_kwargs`** 这一格。  
  你只要**不出现**这一项，就表示**不要自动疯狂试超参数**（省时间、省资源）。

其它像 `hyperparameters`、`known_covariates_names` 等，**不懂就不要加**，系统会用默认的一套模型去练。

4. 全部填好后，点 **Send（发送）**。
5. **等**：训练可能要几十分钟，界面会一直转或卡住一样，**正常现象**。不要狂点重复发送同一个 `task_id`，否则会报错说任务已在跑。

**成功了会怎样？**

- Postman 里会**下载一个 zip 文件**，或让你选保存位置。  
- 把它保存好，文件名随便，例如 **`longhua_model.zip`**。后面推理**全靠它**。

**失败了会怎样？**

- 会有一段英文错误提示。把整段复制给懂技术的同事，或对照下面「常见问题」。

### 2.3 用 curl 怎么复制？（给会命令行的人）

把下面命令里的三处改掉：

- `http://127.0.0.1:8000` → 你们真实地址  
- `@/path/to/longhua_train.csv` → 你电脑上 CSV 的真实路径  
- `longhua_yougo_model_pack.zip` → 你想保存的 zip 文件名（可改）

```bash
curl -X POST "http://127.0.0.1:8000/api/train" \
  -F "task_id=longhua_yougo_20260514" \
  -F "file=@/path/to/longhua_train.csv" \
  -F "target=优购" \
  -F "prediction_length=168" \
  -F "freq=H" \
  -F "use_tsfresh=false" \
  -F "time_limit=3600" \
  -F "enable_ensemble=true" \
  --output longhua_yougo_model_pack.zip
```

执行完以后，当前文件夹里会多一个 zip。

### 2.4 想偷看练到哪了（可选）

如果别人告诉你地址，可以在浏览器打开（把 `task_id` 换成你的）：

```text
http://127.0.0.1:8000/api/task_status?task_id=longhua_yougo_20260514
```

会看到类似「排队中 / 运行中 / 成功 / 失败」的状态。**看不懂 JSON 没关系**，只要看有没有 **SUCCESS** 或 **FAILED** 这类单词。

## 第三步：推理（上传 zip + 最近历史表 → 得到预测 csv）

### 3.1 推理在干什么？

训练得到的 zip 里装的是「已经学会的公式」。  
推理时你要再告诉系统：**最近真实发生过的电量**（还是那张表的形式），系统就输出：**往后 168 小时的预测值**。

推理用的 CSV：

- **列名要和训练时一样**（`timestamp`、`item_id`、`优购` 等）；
- **内容只要「过去」的真实数据**，不需要你先把 5 月 14 日以后的优购填上——系统要算的就是未来。

同样建议：**最后一行历史到 `2026-05-13 23:00:00`**，这样预测出来的 168 小时正好对齐业务说的那一周。

### 3.2 推理的网址

```text
http://你的服务器地址:端口/api/inference
```

### 3.3 Postman 怎么填？

还是 **POST**，**Body** 选 **form-data**。

| Key | 类型 | Value |
|-----|------|-------|
| `task_id` | Text | 再起一个新名字，例如 `longhua_infer_001`（**不要**和训练那次必须相同，不同也行，只要你不搞混就行） |
| `best_model` | Text | **填哪个模型来预测**。新手最省事：先填 **`WeightedEnsemble`**（意思是「综合集成」）。如果训练失败或同事说没有这个名字，让同事打开训练结果里的排行榜（leaderboard）看**第一行模型名**，填那一行的英文名。**不要自己瞎编。** |
| `model_zip` | **File** | 选上一步保存的 **zip**（训练下载的那个） |
| `data_csv` | **File** | 选**推理专用**的历史 CSV（结构和训练一样，时间截到预测起点之前） |

点 **Send**。成功后会得到一个 **csv 文件**，用 Excel 打开就是预测结果。

### 3.4 curl 示例（给会命令行的人）

```bash
curl -X POST "http://127.0.0.1:8000/api/inference" \
  -F "task_id=longhua_infer_001" \
  -F "best_model=WeightedEnsemble" \
  -F "model_zip=@/path/to/longhua_yougo_model_pack.zip" \
  -F "data_csv=@/path/to/longhua_infer_history.csv" \
  --output longhua_infer_001_predictions.csv
```

## 常见问题（对着查）

**1. 提示 409 或 “already running”**  
同一个 `task_id` 上次还没跑完又点了一次。换一个 `task_id`，或者等上一个结束。

**2. 提示找不到文件、路径错**  
curl 里 `@` 后面必须是**真实路径**。Windows 路径类似 `@"D:\data\train.csv"`。

**3. 表头写了「优购 」多空格，或用了全角符号**  
列名必须和 `target` 里填的完全一致，建议直接复制粘贴表头。

**4. 推理结果日期不对**  
检查历史表**最后一行时间**是不是你期望的「预测开始的前一小时」。不对就改表再传。

**5. best_model 填错**  
会报错或结果很怪。问技术同事要「排行榜第一名」的英文名字，或先试 `WeightedEnsemble`。
